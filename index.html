Quantum networking research

When should a quantum repeater swap, wait, or throw a qubit away?

Entanglement has to be built across a long distance one short link at a time. This project finds the best moments to join links together, first with a controller that sees the whole chain, then with nodes that only know what light-speed messages have told them.

Kevin Shan · Undergraduate research at UMass Amherst with Prof. Gayane Vardoyan · Code on GitHub

The problem

A repeater chain, and the decision each middle node faces.

The goal is to deliver one entangled pair between the two end nodes as fast as possible, measured as the expected number of time slots. The obvious strategy, called swap-asap, swaps everywhere the moment it can. The question is when holding off does better, and by how much.

Part 1: a controller that sees everything

An exact Markov decision process, solved by policy iteration.

The model follows Iñesta, Vardoyan, Scavuzzo and Wehner, On the Effect of Quantum Memory Cutoffs in Entanglement Distribution, with one deliberate change. The paper cuts a whole link once the link's age reaches the cutoff, which only makes sense if someone knows the whole link's history. This project uses a qubit-age (retention-time) cutoff instead: each qubit is discarded when its own age reaches \(t_{\text{cut}}\), which a node can check locally. Both conventions share the same topology and probabilities, so they can be compared directly.

The Markov decision process

The state is the age of every qubit. The action is any subset of middle nodes that hold two live qubits, meaning "try a swap here this slot." The empty set means wait, and the full set is swap-asap. Each slot costs a reward of \(-1\) with no discounting, so the value of a state is minus its expected time to delivery:

$$V(s) = -\,\mathbb{E}\left[\text{time slots until an end-to-end link} \mid s\right]$$

The state space is discovered lazily: a state is registered the first time the dynamics actually reach it, so nothing unreachable is ever enumerated.

Solving policy evaluation as one linear system

Policy iteration spends nearly all its time evaluating a fixed policy \(\pi\). The usual approach repeats Bellman backups, and each sweep only pushes information one time step further, which is slow exactly in the interesting regime where links rarely form. For a fixed policy, though, the Bellman equation is a linear system that can be solved outright with one sparse factorization:

$$V = -\mathbf{1} + P_\pi V \quad\Longleftrightarrow\quad (I - P_\pi)\,V = -\mathbf{1}$$

Here \(P_\pi\) is the transition matrix under \(\pi\). The cost then depends on how sparse the transitions are, not on how long the chain takes to deliver, and the answer is exact rather than one tolerance short.

224×

Largest measured speedup of the direct solve over iterative evaluation (4 nodes, \(p=0.25\), \(p_s=0.35\), with voluntary discard).

1.6×

Smallest measured speedup, on easy cases. The direct answer is also the more accurate one.

To check what the optimal policy does to the quantum state itself, a separate simulator replays the solved policy on noisy QuantumSavory registers with depolarization and reports the end-to-end fidelity of the delivered pair.

Part 2: nodes that only know what has reached them

Removing the all-seeing controller turns the problem into a decentralized, partially observable one.

Part 1 assumes a controller that sees every qubit's age instantly. That is physically wrong. A swap is a local measurement whose result has to be announced, and the announcement travels at the speed of light, one hop per time step in this model. The far end of a link cannot know its link was consumed or destroyed until that message arrives.

Without that assumption, the problem becomes a decentralized partially observable Markov decision process (Dec-POMDP). Each node acts on a local observation, and a node cannot tell a live link from a dead one. That produces the effect the whole investigation centers on: hanging qubits, which are stored, ageing and blocking new links even though their partner is already gone.

One time step, in six phases

  1. Every stored qubit ages by one slot.
  2. Every empty elementary link attempts generation. Success is heralded to both ends immediately, which is the only knowledge in the model that is not delayed.
  3. Classical messages from the neighbours arrive.
  4. Every node acts on its own delayed view: swaps first, then voluntary discards.
  5. The cutoff removes anything that has reached \(t_{\text{cut}}\).
  6. Every node tells its neighbours what it now knows.

Two kinds of message travel. A flooded age ledger reaches the whole chain and gets one time step staler per hop. Targeted announcements are sent only when something happens to a link (an update after a successful swap, a delete after a failed swap or a discard), and they are addressed to a specific occupancy of a slot so that a late message cannot corrupt a newer link.

Policies are solved with JESP (Joint Equilibrium-based Search for Policies): hold every other node fixed, compute one node's best response from Monte-Carlo rollouts, solve that with the same sparse linear system as Part 1, and repeat. A Python port of the dynamics is checked against the Julia physics simulator with a two-sample z-test on mean delivery time.

What was learned

10–13%

of all swap-asap swaps used at least one hanging input, over 3,000 episodes on a 5-node chain.

~23%

of all occupied slot-time was spent on qubits that were already useless (\(p=0.9\), \(t_{\text{cut}}=6\)).

Swapping against a hanging qubit also destroys the good link. The swap fails deterministically, both local qubits are consumed, and the healthy side's far end becomes a new hanging qubit that will not find out for several time steps.

A cutoff-aware policy helps, but only when the cutoff is long enough for the news to arrive in time. It discards a qubit as soon as a delete message reaches it, or when the ledger says the far end must already be past its cutoff.

The ledger channel never fired. Every improvement came from the targeted messages, because a delete message always arrives at least as early as anything the ledger could infer. The staleness feature is the open lead: every node observes how long ago each belief was confirmed, and neither handwritten policy uses it yet.

Run it

Python 3.12 or newer with uv, plus Julia for the fidelity simulators.

git clone https://github.com/kevinshan0/REU
cd REU/linear-repeater-chain
uv sync
julia --project=. -e 'using Pkg; Pkg.instantiate()'

# optimal policy, exact sparse evaluation
uv run python src/policy.py --n 5 --p 0.9 --p_s 0.5 --cutoff 2 --method direct

# swap-asap baseline
uv run python src/policy.py --n 5 --p 0.9 --p_s 0.5 --cutoff 2 --policy swap-asap

# delayed-information model: verify against the simulator, then solve with JESP
uv run python src/info_delay_solver.py --verify --n 5 --p 0.9 --p_s 0.9 --t-cut 6
uv run python src/info_delay_solver.py --n 5 --p 0.9 --p_s 0.9 --t-cut 6 --simulate

The full write-ups are in the repository: qubit-age cutoffs, the sparse evaluation, the delayed-information model and a step-by-step trace of two episodes.
